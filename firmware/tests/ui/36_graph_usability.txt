# Graphing usability (docs/usability/graphing.md): the Y= mode header is in
# view, typing on it goes to the first entry, the Y= MENU options, an empty
# graph and an empty TRACE say what to do, CALC prompts say how to answer,
# intersect picks the curves itself when there are only two, WINDOW / TBLSET
# explain the selected field and name what is wrong, TABLE goes to a typed x.
# --- Y=: the graph-mode header is visible on arrival
key F1
expect screen yeq
expect state yeq_row 0
expect text PAR
expect text IMPL
# typing on the header goes to the first entry (nothing is lost)
key UP
expect state yeq_row -1
type "x^2-2"
expect state yeq_row 0
expect state y1 x^2-2
# a tap on the header chooses the mode and puts the focus on its first entry
touch tap 40 29
expect state graph_type PAR
expect state yeq_row 0
type "cos(x)"
expect state e1_1 cos(t)
touch tap 10 29
expect state graph_type FUNC
expect state y1 x^2-2
# --- the MENU key: options of the focused entry and the graph modes
key MENU
expect screen menu
expect state menu "Y= OPTIONS"
expect text "Y1 on/off"
expect text "Y1 next line style"
screenshot yeq_menu.png
key 1
expect screen yeq
expect state y1_on 0
key MENU 1
expect state y1_on 1
key MENU 2
expect state y1_color red
key MENU 3
expect state y1_style thick
key MENU 3 MENU 3 MENU 3 MENU 3 MENU 3
expect state y1_style line
# graph mode from the menu (item 6 = PAR), and back (item 5 = FUNC)
key MENU 6
expect state graph_type PAR
expect state yeq_row 0
key MENU 5
expect state graph_type FUNC
# clear the entry from the menu, then retype it
key MENU 4
expect state y1 ""
type "x^2-2"
# --- an empty graph says where its content comes from; TRACE says why it cannot start
key SHIFT LEFT LEFT ENTER
