# Sparkle Town: the second code review (bugs, and changes that make bugs less likely)

Reviewed at commit `a6d2e51` (branch `worktree-agent-ae58ab739bd649fe1`), 2026-10-23. The first review is
`CODE_REVIEW.md` (CR-01..CR-18); its fixes were checked on the way and are not re-reported. The module's game
code was not changed; the review adds two unit checks (part B) and the repro scripts and screenshots in
`code_review2/`.

Method: every touch handler read against the widget library's contract (a real tap is a DOWN then a TAP, never
an UP: `core/touch.c:132-137`; the library turns that into one event for most kinds and two for a few), every
scene's raw `type == 1 / 4` paths, the widget set's state across screens; then three focused reads for the other
classes (pictures against their text; integer widths, saves and bounds; transitions, hooks and judging). Every
confirmed finding was reproduced on `build/sim/calcsim` (ASan + UBSan) with `tests/run_ui.py`; the scripts are
console lines after the usual setup (`fs insert 64`, `fs format`, `module library extra`, `module install
/CALC/MODULES/MATHQ010.MOD`, `key CLEAR`, `app mathquest`) and run with
`python3 tests/run_ui.py --sim build/sim/calcsim --shots DIR SCRIPT`; the lines that fail are the bug (an
`expect` of the right behaviour).

Severity: S1 crash, freeze, corrupted save or wrong judging; S2 visible wrong behaviour (a kid is stuck, misled or
robbed of what she did); S3 minor; S4 polish.

## Summary

24 findings: confirmed on the simulator 22 -- S1 x3 (CR2-21 a grown-up's preview answer booked as hers, CR2-11 the bulb's picture gives the odd/even order the wrong
answer, CR2-12 the card prints the answer), S2 x12 (CR2-01, 02, 03, 04, 05, 07, 09, 13, 14, 15, 19, 22), S3 x6
(CR2-08, 16, 17, 18, 20, 24), S4 x1 (CR2-10); suspected from reading 2 -- S4 (CR2-06), S3 (CR2-23 is confirmed; its stars are dead code).

The user's report: **CR2-01** -- the "house of places" trick never names the number (306) she is to build: `expr()`
has no case for it and its step says "Drag discs into the houses" without the number. Its sibling class is the
pictures that name the wrong thing or the answer (CR2-11..17).

The recurring class, hunted across every touch handler: a real tap is a DOWN then a TAP. Four more handlers act on
both (CR2-02 the room's tap deselects, CR2-03 the gate's tap holds, CR2-04 a bongo tap drums twice, CR2-06 a
bubble beat pops twice), and the guard that was meant to end the class in the games fails for a one-frame tap on an
even tick (CR2-05: the `anim_t | 1` mark reads as the future). Two more input-state bugs: a thing "picked" on one
screen is dropped on the next (CR2-07: a $1 coin on the till's tray she never touched) and a flick is looked up at
the finger's end (CR2-08).

Part B lists twelve changes; the five that matter most: B1 one press-or-tap rule with a helper for the raw screens,
B2 a time mark that never lies (`mq_mark` / `mq_since`), B4 one source of truth for what a picture may show, B3
the widget set reset on every screen change, B8 judging that cannot be reached from a preview or with a made-up
answer. Part C has what was implemented here (two unit checks that pin the contracts and print the open bugs as
known gaps, two static asserts).

## A. Bugs

### The tap class: a real tap is DOWN then TAP

The widget library (`mq_widget.c:189-333`) sends a WG_AREA a WHY_PRESS on the DOWN and a WHY_TAP on the TAP, an
on-down choice its WHY_TAP on the DOWN (and swallows the TAP for 1.5 s), a slider the same value twice; the
screens that read raw touches (`type == 1` and `type == 4`) get both too. A handler that acts on both acts twice.
The Pie Shop (4ac9a30) and CR-06 were this; four more below (CR2-02, 03, 04, 05), each reproduced, plus the guard
that was meant to end the class in the games (CR2-05) failing half the time.
