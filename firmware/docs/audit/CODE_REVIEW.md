Reviewed at commit `40b506d` (branch `worktree-agent-a7e89116d1387c170`), 2026-10-22/23. Read-only: nothing in
`modules/mathquest` was changed; the repro scripts and screenshots are in `code_review/`.

Method: a systematic read of `mq_main.c` (scenes, input, save migration), `mq_play.c` (the round, the games, widgets),
`mq_vis.c` (the models), `mq_engine.c`, `mq_learn.c`, `mq_facts.c`, `mq_rung.c`, `mq_coach.c`, `mq_purse.c`, `mq_home.c`,

(entry points), `mq_widget.c`, `mq_hr.c`, `mq_events.c`, `mq_action.c`, `mq_story.c` (wrap/expand), `mq_toys.c` (the jam).
Where cheap, a finding was reproduced on `build/sim/calcsim` with `tests/run_ui.py` (scripts in `code_review/`).

Severity: S1 wrong judging / lost progress / crash; S2 a kid is stuck or misled; S3 visible but survivable; S4 polish.

Repro scripts are console lines for `build/sim/calcsim` after the usual setup (`fs insert 64`, `fs format`,
`module library extra`, `module install /CALC/MODULES/MATHQ010.MOD`, `key CLEAR`, `app mathquest`); run them with
`python3 tests/run_ui.py --sim build/sim/calcsim --shots DIR SCRIPT`. Some scripts carry `expect state KEY ""` lines
that fail on purpose: `run_ui.py` prints the state's value only on a failed expect, so those lines are how the script
shows the number it is about (the tips, the unlocks, the question's text and answer).

## Summary

Confirmed (reproduced on the simulator, or deterministic from the code): 8 -- S1 x2 (CR-01, CR-05), S2 x2 (CR-02,
CR-12), S3 x3 (CR-03, CR-04, CR-06), S4 x1 (CR-13). Suspected (from reading): 7 -- S2 x1 (CR-10), S3 x1 (CR-11), S4 x5
(CR-14 to CR-18).

The one to fix first is CR-01: every question picture that fills "n of d" (pies, bars, hundredths grids, picture
graphs, angles, rulers) draws one unit fewer than the order's data, so a child who reads the picture correctly is
judged wrong. It is a one-line cause (`mq_visual` caps a question's `reveal` at 999) and it explains the "pink cake
with no pink" report.

## Notes on areas checked and found sound

- Save migration (`mq_main.c:3809-3920`): the v1-3 conversion, the v4/v5 prefix reads, the fresh path, the name copy
  and the rung / fact / purse migrations are consistent; `B_RESET` and a new player clear the profile, home, learn,
  extra and more blocks (`mq_extra_migrate` zeroes `more` too).
- The hook-panel leak (bot finding 1) is fixed (`mq_fun.c:651`); the grown-ups' gate by touch (bot 2) is fixed.
- `add_opt` always puts the right answer first (`mq_play.c:349`), so "the answer is always an option" holds for every
  pick game; the pink-cake report was the picture (CR-01), not the options.
- The widget hit-test grows every box to 48 x 48 and picks the nearest centre; moving answers are picked on DOWN
  (`WF_ONDOWN`) with a 1.5 s guard against the TAP that follows (`mq_widget.c:285-298`) -- but only while the game is
  still in GS_PLAY (CR-06).
- Toasts raised on the town show and clear there (checked with a forced birthday: `mq event birthday 1` on the map).
- Theme-pack parsing (`mq_theme.c:102-181`) bounds every count (cells, sprites, colours, items) and every pixel index
  before use; the merge board's cell indices are range-checked at every entry point (`mq_merge.c:292-353`).
- Every accumulated `k += snprintf(...)` write (mq_main, mq_play, mq_purse, mq_steps, mq_strat) stays inside its buffer
  for the inputs the generators can produce (the longest: three 45-character lines into `3 * MQ_TXT + 4`).
- Lock wheels (`lock_make` / `lock_value`), the K_FRAC / K_TIME / K_MONEY parsers and `mq_correct`'s equivalence are
  consistent with the generators' encodings; the Heist's wheel count equals the answer's digit count by design.
- `mq_purse_compose` / `mq_coins_fewest` / `set_bal`: the handful always sums to the balance (`tidy`), the balance is
  capped at `HM_COINS_MAX`; paying over returns change through `complete()`.
- Static sizes: `sizeof(mq_home_t) == 1024` is asserted; `mq_hr_shape`'s array fits 48 polygon points; `ban[]` is indexed
  by `skill < 86`; `near_miss` and `lab[4][16]` are within bounds.
